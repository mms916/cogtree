# 数据库表结构详细设计文档（V1）

## 1. 文档信息

- 文档名称：数据库表结构详细设计文档
- 所属产品：CogTree / 模型树阅读法
- 文档类型：数据库设计文档
- 版本：V1.0
- 文档目标：明确产品核心数据库表、字段、约束、索引、关系、事务边界与演进建议，支撑 Tree First、来源追溯、命令系统与三大核心页面落地

---

## 2. 设计目标

本数据库设计需要同时满足以下目标：

1. 支撑三大核心流程：金句提炼 → 书内修剪 → 主题整理
2. 落实 Tree First 原则，避免双真相源
3. 支撑 Quote → QuoteCard → BookNode → ThemeNode 的来源链路
4. 支撑命令式更新、自动保存、撤销重做、版本控制
5. 兼顾结构化核心字段与高扩展性的 JSONB 字段
6. 为后续 AI、搜索、导出、协作预留空间

---

## 3. 总体设计原则

## 3.1 Tree First

树结构是唯一真相源，以下字段构成结构真相：
- parent_id
- children_ids_json
- order_index

不允许 edges 成为与 tree 并列的主真相源。

## 3.2 核心关系表 + JSONB 混合建模

### 关系表承载
- 用户
- 书籍
- 章节
- 金句
- QuoteCard
- BookTree / BookNode
- ThemeTree / ThemeNode
- 来源映射
- 复盘
- 命令日志

### JSONB 承载
- 节点 UI 元信息
- 扩展配置
- 非关键视图状态
- AI 建议结果
- 导出配置

## 3.3 命令可追溯

关键结构操作必须可回溯，因此需要命令日志表与版本字段。

## 3.4 主从层级清晰

链路为：
- 原文：quotes
- 初步提炼：quote_cards
- 书内稳定节点：book_nodes
- 主题节点：theme_nodes

## 4. ER 关系总览

## 4.1 核心实体

- users
- books
- chapters
- quotes
- quote_cards
- book_trees
- book_nodes
- theme_trees
- theme_nodes
- source_mappings
- reviews
- command_logs

## 4.2 核心关系

### 用户与书籍
- 一个 user 拥有多本 books

### 书籍与章节
- 一本 book 拥有多个 chapters

### 章节与金句
- 一个 chapter 拥有多个 quotes

### 金句与 QuoteCard
- 一条 quote 对应零个或一个主 quote_card（第一版建议 1:1）

### 书籍与书内树
- 一本 book 对应一个主 book_tree（第一版）
- 通过 version 实现版本演进

### 书内树与书内节点
- 一个 book_tree 拥有多个 book_nodes

### 主题与主题树
- 一个用户可拥有多个 theme_trees
- 一个 theme_tree 拥有多个 theme_nodes

### 来源映射
- source_mappings 连接 theme_nodes 与 book_nodes

### 复盘
- reviews 可关联书籍和主题

### 命令日志
- command_logs 记录对树和节点的命令操作

## 5. PostgreSQL 约定

## 5.1 主键策略

建议统一使用：
- `uuid`

原因：
- 适合分布式/前后端分离
- 前端本地创建临时节点后便于过渡
- 不依赖数据库自增序列暴露业务规模

## 5.2 时间字段约定

统一使用：
- `created_at timestamptz not null default now()`
- `updated_at timestamptz not null default now()`

## 5.3 软删除策略

第一版建议核心结构表先不引入全量软删除字段，避免复杂度过高。

仅对以下场景可预留：
- nodes
- reviews

可选字段：
- `deleted_at timestamptz null`

## 5.4 JSONB 命名约定

所有 JSONB 扩展字段统一后缀：
- `_json`

例如：
- `meta_json`
- `tags_json`
- `candidate_nodes_json`

## 6. 表设计：users

## 6.1 作用

用户主表。

## 6.2 表结构

```sql
create table users (
  id uuid primary key,
  email text not null unique,
  password_hash text not null,
  display_name text not null,
  avatar_url text,
  status text not null default 'active',
  settings_json jsonb not null default '{}'::jsonb,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);
```

## 6.3 约束建议

- `email` 唯一
- `status` 可选值：active / disabled / invited

## 6.4 索引建议

```sql
create unique index ux_users_email on users(email);
```

## 7.3 索引建议

## 11. 表设计：book_trees

## 11.1 作用

书内树主表，用于承载一本书当前版本的结构树元数据。

## 11.2 表结构

```sql
create table book_trees (
  id uuid primary key,
  book_id uuid not null references books(id) on delete cascade,
  version integer not null default 1,
  root_node_ids_json jsonb not null default '[]'::jsonb,
  current_status text not null default 'active',
  stats_json jsonb not null default '{}'::jsonb,
  meta_json jsonb not null default '{}'::jsonb,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  unique(book_id, current_status)
);
```

## 11.3 current_status 建议

- active
- archived

### 说明
第一版可约定每本书只有一个 active 的主 tree。

## 11.4 索引建议

```sql
create index idx_book_trees_book_id on book_trees(book_id);
create index idx_book_trees_book_id_version on book_trees(book_id, version desc);
```

## 12. 表设计：book_nodes

## 12.1 作用

BookNode 是书内修剪台的核心节点表。

## 12.2 表结构

```sql
create table book_nodes (
  id uuid primary key,
  tree_id uuid not null references book_trees(id) on delete cascade,
  book_id uuid not null references books(id) on delete cascade,
  label text not null,
  node_type text not null,
  parent_id uuid references book_nodes(id) on delete set null,
  children_ids_json jsonb not null default '[]'::jsonb,
  order_index integer not null default 0,
  short_definition text,
  full_definition text,
  theme_ids_json jsonb not null default '[]'::jsonb,
  source_quote_ids_json jsonb not null default '[]'::jsonb,
  source_chapter_ids_json jsonb not null default '[]'::jsonb,
  note_count integer not null default 0,
  pending_question_count integer not null default 0,
  confidence_score numeric(5,2),
  review_status text not null default 'normal',
  status text not null default 'normal',
  meta_json jsonb not null default '{}'::jsonb,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);
```

## 12.3 node_type 枚举建议

- concept
- cause
- effect
- mechanism
- question
- note
- abstract
- pending

## 12.4 review_status 枚举建议

- normal
- pending_review
- pending_verify
- merge_candidate
- duplicated
- low_confidence

## 12.5 status 枚举建议

- normal
- selected
- editing
- collapsed
- hidden_by_filter

### 说明
`selected/editing` 更偏前端状态；数据库可只持久化长期状态，前端临时态不一定落库。

## 12.6 索引建议

```sql
create index idx_book_nodes_tree_id on book_nodes(tree_id);
create index idx_book_nodes_book_id on book_nodes(book_id);
create index idx_book_nodes_parent_id on book_nodes(parent_id);
create index idx_book_nodes_order on book_nodes(tree_id, parent_id, order_index);
create index idx_book_nodes_label on book_nodes(tree_id, label);
```

## 12.7 Tree First 约束说明

- `parent_id` 是结构真相源的一部分
- `children_ids_json` 是结构真相源的一部分
- 二者必须在命令执行中保持一致
- 不允许只改其中之一

## 15. 表设计：source_mappings

## 15.1 作用

连接 ThemeNode 与 BookNode，是主题整理页来源追溯的核心桥表。

## 15.2 表结构

```sql
create table source_mappings (
  id uuid primary key,
  theme_node_id uuid not null references theme_nodes(id) on delete cascade,
  book_node_id uuid not null references book_nodes(id) on delete cascade,
  book_id uuid not null references books(id) on delete cascade,
  mapping_type text not null default 'direct',
  strength numeric(5,2),
  meta_json jsonb not null default '{}'::jsonb,
  created_at timestamptz not null default now(),
  unique(theme_node_id, book_node_id)
);
```

## 15.3 mapping_type 枚举建议

- direct：直接映射
- merged：多节点整合后映射
- abstracted：经过抽象提升后映射

## 15.4 索引建议

```sql
create index idx_source_mappings_theme_node_id on source_mappings(theme_node_id);
create index idx_source_mappings_book_node_id on source_mappings(book_node_id);
create index idx_source_mappings_book_id on source_mappings(book_id);
```

## 17. 表设计：command_logs

```sql
  tree_type text not null,
  tree_id uuid not null,
  target_type text not null,

```

## 17.3 tree_type 枚举建议

- book_tree
- theme_tree

## 17.4 command_name 示例

- renameNode
- createNode
- moveNode
- reorderNode
- deleteNode
- mergeNodes
- splitNode
- elevateAbstract
- attachQuoteCard
- bindSourceMapping

## 17.5 索引建议

## 19. 约束与一致性规则

## 19.1 树结构一致性

必须保证：
- 一个 node 的 `parent_id` 与父节点 `children_ids_json` 一致
- 同级 `order_index` 合法
- 不允许循环引用

## 19.2 删除规则

### 删除 quote
- 级联删除 quote_card
- BookNode 不应自动删除，但要保留来源丢失检查机制（后续）

### 删除 book_tree / theme_tree
- 级联删除所属节点

### 删除 book_node
- 若被 source_mappings 引用，需级联清理映射

## 19.3 唯一性规则

- `quote_cards.quote_id` 唯一
- `source_mappings(theme_node_id, book_node_id)` 唯一
- 每本书仅一个 active book_tree
- 每个用户在同一 theme_id 下仅一个 active theme_tree

- moveNode

- node 变更

## 23. 建议迁移顺序

建议 Prisma / SQL migration 按以下顺序推进：

1. users
2. books
3. chapters
4. quotes
5. quote_cards
6. book_trees
7. book_nodes
8. theme_trees
9. theme_nodes
10. source_mappings
11. reviews
12. command_logs

原因：
- 从基础对象到结构对象
- 从单书到主题
- 从业务主表到日志表

---

## 24. 第一阶段最小可落地库表集合

如果要尽快进入开发，第一批必须落地：

- users
- books
- chapters
- quotes
- quote_cards
- book_trees
- book_nodes
- theme_trees
- theme_nodes
- source_mappings
- command_logs

复盘 reviews 可稍后落地。

## 25. 一句话总结

这套数据库设计的核心，不是“把页面数据存下来”，而是围绕 **Tree First、来源可追溯、命令可回放** 三条主线，构建一个能支撑金句提炼、书内修剪、主题整理持续演进的知识结构底座。
